# issuer-revenue-period-reconciliation
## Requirements
- `input-envelope`: reconcileIssuerRevenueFacts receives one object {cik,asOf,periodKind,maximumAgeDays,companyfacts}; cik is exactly ten decimal digits, asOf a real calendar date YYYY-MM-DD periodKind quarter or annual, maximumAgeDays a positive integer, companyfacts an object whose numeric/string cik denotes same requested integer and whose entityName is a nonempty string and facts object exists. Return TypeError for invalid envelope or malformed identity. Do not mutate inputs.
- `date-domain`: Parse exact UTC calendar days and reject rollover dates. Eligible observations have finite numeric val, valid start,end,filed day with start<=end<=asOf and filed<=asOf, nonempty accn and form in `10-Q`,`10-Q/A`,`10-K`,`10-K/A`. An invalid observation is excluded, not repaired. fy/fp/frame are not used as dates or duration.
- `concept-domain`: Inspect only facts.us-gaap concepts in this fixed order: Revenues, SalesRevenueNet, RevenueFromContractWithCustomerExcludingAssessedTax. Inspect only each units.USD array; absent concept/units/array contributes no facts. Never merge USD with shares or another unit.
- `duration-domain`: DurationDays is inclusive UTC end-start calendar days. Requested quarter accepts {{quarter-minimum-days}} through {{quarter-maximum-days}} inclusive days, annual {{annual-minimum-days}} through {{annual-maximum-days}} inclusive days. Exclude nine-month/YTD facts from quarter; never derive Q4 or convert currencies.
- `selection`: Eligible facts for coverage need not match requested duration. For selected period consider only eligible requested-duration facts, choose greatest actual end date. If two starts share that greatest end then status ambiguous, period null, value null and keep all candidate witnesses sharing greatest end. Do not use array order, fy or fp for selection.
- `witnesses`: A witness has exactly concept,start,end,durationDays,value,unit USD,form,filed,accession fields. Convert source val to value and accn to accession; preserve numbers exactly. Deduplicate only exact equal witness objects; sort witnesses by concept lexical, then filed lexical, then accession lexical, then value numeric, then start lexical, then form lexical. Selected witnesses are ALL eligible requested-duration facts at the selected exact start/end, including older filing witnesses.
- `conflict`: For a single selected start/end, within EACH concept take greatest filed date and ALL witnesses on that date. If the union of these latest per-concept witnesses has more than one distinct numeric value, status ambiguous,value null,revision ambiguous. No sum or concept precedence resolves conflict.
- `revision`: For unambiguous selected value, if an earlier-filed witness has a different value revision is changed-reported-value. Otherwise if multiple distinct accession strings occur revision is equal-value-rereport, otherwise none. These labels do not assert an audited accounting restatement. Multiple-start ambiguity has revision ambiguous.
- `staleness`: For unambiguous period/value, UTC day difference asOf minus period end greater than maximumAgeDays gives status stale, otherwise current. Preserve stale period/value and witnesses. No candidates gives status missing,period null,value null,witnesses empty,revision none. Ambiguity takes precedence over stale.
- `coverage`: conceptCoverage is an array in fixed concept order; each element has exactly concept,latestEnd,count, where count is number of deduplicated eligible witnesses of ALL durations for this concept and latestEnd maximum eligible end or null. This is scoped to inspected USD concepts and date cutoff, not a claim of exhaustive latest SEC filing.
- `output`: Return exactly `{type:"IssuerRevenueReconciliation",version:1,cik,issuer:companyfacts.entityName,asOf,periodKind,status,unit:"USD",period,value,witnesses,conceptCoverage,revision}`. A nonnull period has exactly start,end,durationDays. Preserve requested cik string/asOf/periodKind; no ranking or investment recommendation.
- `api`: Export reconcileIssuerRevenueFacts from src/issuer-revenue-reconciliation.mjs as the reusable pure semantic kernel. Other procurement, source identity, original evidence packet constructor, market binding, commercial receiving and deployment remain separate original Work obligations.
## Prohibitions
- `no-effects`: No network, clock, filesystem, process, credentials, inference, broker, payment, environment access or retained writes; no dependency imports required. All source facts and dates arrive explicitly as data. [claims: bounded-product-contract]
- `no-guesses`: Do not fabricate facts, use filing fy/fp for actual period, choose a legacy tag by precedence, average conflicting values, calculate a missing quarter, or count a schema/test outcome as outside revenue. [claims: bounded-product-contract]
- `no-identity-duplication`: Do not implement or replace packet identity, canonical JSON, generic parsers or the original formIssuerEvidencePacket. This kernel emits factual data only, for the existing packet constructor's later composition. [claims: bounded-product-contract]
