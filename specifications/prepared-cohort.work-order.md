# issuer-revenue-prepared-cohort
## Requirements
- `configuration`: Validate the complete trusted configuration before effects: issuers is an array with at least {{minimum-issuers}} and at most maximumIssuers unique ten-digit CIKs and nonempty tickers; maximumIssuers is an integer between {{minimum-issuers}} and {{maximum-issuers}}; userAgent is a string whose trim is nonempty, contains no CR or LF and includes literal @; this exact trusted-header structural predicate does not establish mailbox grammar, deliverability or truthful operator identity, which the actual operator independently receives; maximumBytes, timeoutMs, maximumSnapshotAgeMs, maximumCohortBytes and both maximumAgeDays values are positive safe integers. minimumIntervalMs is an integer at least {{minimum-interval-ms}}. cacheKey is a nonempty string. allowedPeriodKinds is a nonempty unique subset of quarter/annual; allowAmbiguousEvidence is boolean. Invalid configuration throws TypeError before any acquisition/cache read. Configuration is host-owned, never granted by public request. Additional host metadata fields are allowed and ignored; only the enumerated supplier fields affect this module. In particular enabled/resourceAdmission are admission controls of the actual coordinator, not interpreted or granted by this supplier.
- `acquisition-plan`: planIssuerRevenueAcquisition(configuration) returns exactly the demonstrated IssuerRevenueAcquisitionPlan shape, retaining configured issuer order, CIK/ticker, fixed HTTPS data.sec.gov companyfacts URL derived solely from each CIK, User-Agent and Accept headers, per-request timeout/maximumBytes, minimumIntervalMs and maximumCohortBytes. No arbitrary URI/redirect/provider from the customer. Planning is pure and grants no execution or quota.
- `public-request`: validateIssuerRevenueComparisonRequest(body,configuration) validates configuration and accepts exactly a record containing only periodKind that is in configuration.allowedPeriodKinds, returns a fresh {periodKind}; otherwise throws TypeError with no I/O. The first actual offer permits annual only; reusable code preserves other explicitly configured period kinds. No body-supplied issuers, dates, cache keys, buckets, source or config.
- `selector-input`: selectPreparedIssuerRevenueComparison receives {body,configuration,cohort,now}. now is a canonical UTC ISO millisecond instant string or finite integer epoch milliseconds; invalid now throws TypeError. Validate public request first. An inadmissible cohort/readiness condition throws Error with code issuer-revenue-unavailable, status equal to `503`, retryable true. Every malformed or unavailable cache condition uses that same cache error; only invalid request/configuration/explicit-now arguments use TypeError. It never returns an unavailable JSON value as paid fulfillment.
- `cohort-boundary`: A prepared object has type IssuerRevenuePreparedCohort, version `1`, canonical UTC observedAt, real YYYY-MM-DD asOf equal to observedAt's UTC day, and results with quarter/annual properties. It must not be future-dated; now minus cohort observedAt must not exceed maximumSnapshotAgeMs. The selected result has type IssuerRevenueComparison, version `1`, same asOf/observedAt and requested periodKind, datePolicy filing-date-cutoff-on-received-sources. No date precision beyond the received snapshot is asserted.
- `configured-cohort`: Selected issuers and evidencePackets are arrays exactly matching configured count and order. Each issuer result has type IssuerRevenueReconciliation, version `1`, matching configured cik/ticker and asOf/periodKind, nonempty issuer, USD unit, valid source {uri,digest,bytes,observedAt}. URI is the fixed configured CIK URL; digest is admitted by existing isNiUri; bytes is a positive safe integer no greater than maximumBytes; source observation is no later than cohort and no older than maximumSnapshotAgeMs relative to now. Reject mismatched, duplicate, missing or extra issuers.
- `financial-freshness`: Selected status must be current or, only with allowAmbiguousEvidence true, ambiguous. Missing or stale refuses. Current has finite value, valid nonnull actual period and nonempty witnesses. Ambiguous has null value and nonempty witnesses; it may have a null period when multiple starts share its latest end. Every selected witness has valid actual start/end, matching declared durationDays, start no later than end and end no later than asOf, requested duration class (quarter inclusive {{quarter-minimum-days}} through {{quarter-maximum-days}} days; annual inclusive {{annual-minimum-days}} through {{annual-maximum-days}} days), finite value, USD unit, form exactly one of `10-Q`, `10-Q/A`, `10-K`, `10-K/A`, filed no later than asOf and nonempty accession/concept. Check period end against actual now UTC day and configured maximumAgeDays even for ambiguity; kernel ambiguity precedence never licenses ancient conflicting evidence. Do not recompute raw facts or choose among conflicts.
- `prepared-packets`: Each original evidence packet has type IssuerEvidencePacket/version `1`, ticker equal to String(configured ticker).toUpperCase(), same issuer/asOf, nonempty id admitted by existing isNiUri, brokerageEffect false, sources exactly one matching that issuer's URI/digest/observedAt, and exactly one claim with sourceDigests exactly [that digest] and statement exactly the producer contract's literal reconciliation statement derived from the selected structured issuer result: 'Received SEC companyfacts and reconciled '+periodKind+' USD revenue; status='+status+'; period='+(period?start+'..'+end:'none')+'; value='+String(value)+'; revision='+revision+'.'. Reject a packet statement that disagrees with structured status, period, value or revision even when its source citation is valid. This compares declared content only and never regenerates or verifies packet identity. This is trusted cache boundary validation, not cryptographic recertification: do not regenerate packet identities on the paid path. No contrary packet/source can pass.
- `return-unchanged`: For an admitted complete selected result return that exact result unchanged. Its comparability is aligned-periods only when all statuses current and their exact start/end align, different-periods when all current but starts/ends differ, otherwise unresolved. Reject inconsistent comparability or date metadata. For period/value metadata, current requires finite numeric value and nonnull valid period whose start/end/duration match every witness. Within each witness concept, identify its greatest filed date; every witness at that concept's greatest filed date must equal the reported current value. Distinct concepts with different latest values, or same-concept latest-date conflicts, cannot pass as current. Earlier filing witnesses may legitimately differ and must remain retained, so do not require all historical values equal. This compact consistency check consumes the received witness set, never rescans raw companyfacts or chooses a conflicting value; ambiguous requires value exactly null and revision ambiguous, with either a valid nonnull period matching every witness and more than one distinct latest-per-concept value, or a null period whose witnesses share one end but have multiple starts. This is compact typed-boundary validation, not a second raw-facts kernel. No ranking, prediction, investment instruction, automatic quote conversion or claim of earned revenue.
